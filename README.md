# 番茄小说 自动发布工具

把写好的一整本小说（一个 `novel.txt`）**自动拆分、自动校验、自动填进番茄小说后台、自动走完多步发布流程**，
并自己核对后台确认真的发出去了。

面向「不想对着后台一章一章复制粘贴」的作者。Windows 上**双击一个 .bat 就跑**，不需要懂命令行。

> ⚠️ **先说清楚三件事**
> 1. 本工具操作的是**你自己的账号、发布你自己的内容**。内容准确性与合规性由使用者自行确认。
> 2. 自动化操作平台有**触发风控 / 违反平台规则**的风险。脚本内置了间隔与随机浮动来模拟人工节奏，
>    但**风险由使用者承担**。建议先用「试运行」和「自检」摸清流程再加量。
> 3. 番茄后台一旦改版，元素识别可能失效。项目里带了探查与诊断脚本（见 [`tools/README.md`](tools/README.md)），
>    按里面的方法 dump 一份页面结构通常就能修好。

## 它能做什么

| 能力 | 说明 |
|---|---|
| **一键发布** | 双击 `4-一键发布.bat`：校验格式 → 拆分章节 → 打开浏览器 → 检测登录 → 填序号/标题/正文 → 走完多步提交 → 核对后台。**全程不用你做选择** |
| **多步流程自动推进** | 番茄的提交是「编辑页 → 内容检测方式 → 发布设置 → 确认发布」四段。脚本按轮次推进、逐层处理弹窗 |
| **结果真的被验证** | 不只看页面提示。发布完会**重新读后台章节数**，变了才算成功 —— 页面会骗人，后台不会 |
| **不会重复发布** | 发布记录按**标题**和**章节序号**双通道判定。改标题也不会重发（序号发过就是发过） |
| **每日字数配额** | 你设个上限（如 10000 字/天），点一次就**一直发到"下一章放不下"为止**，绝不为一章截断。账本跨天自动清零 |
| **自动切换分卷** | 小说里写一行 `第二卷：云隐谷`，发布时自动把后台的「分卷」切过去 |
| **多本书并存** | 一本一个文件夹，正文/记录/账本各自独立，互不干扰，也不会串号 |
| **浏览器自适应** | 自动探测本机 13 种 Chromium 系浏览器（Chrome/Edge/Brave/360/QQ/搜狗…）并有序回退，坏一个换下一个 |
| **可视化面板** | 本地网页面板：看进度、看额度、点按钮、**实时**看日志 |
| **定时发布** | 走 Windows 任务计划，每天定点自动跑 |
| **格式前置校验** | 编码（GBK/UTF-8/BOM）、换行符、标题识别、字数、分卷、结构遗漏，逐条报告"第几行、错在哪、怎么改" |

## 快速开始

### 0. 前置

- **Windows**
- **Node.js 18+**（[nodejs.org](https://nodejs.org)）
- 一个番茄小说的**作者账号**

### 1. 装依赖

双击 **`0-安装依赖.bat`**。它会装 `playwright-core`，并顺手下一个自带浏览器内核（约 150MB，可跳过）。

> 有 Chrome 或 Edge 的话**不需要**那个自带内核，脚本会优先用你系统里的浏览器。
>
> 装不动 / 报 `ETIMEDOUT` 的话：仓库里的 `package-lock.json` 指向国内镜像
> `registry.npmmirror.com`（番茄作者一般在国内，用它更快）。在海外或镜像不通时，执行
> `npm install --registry=https://registry.npmjs.org` 即可。

### 2. 告诉它你的账号

复制 `templates/credentials.example.json` → 改名为 `credentials.json` → 填上手机号和密码。

或者**不建这个文件**也行：双击 `1-首次登录.bat` 手动登一次，之后登录状态会一直保留。

### 3. 放你的小说

双击 **`11-切换当前小说.bat`** → 输入 `0` 新建一本 → 会生成 `books\<书名>\` 文件夹。
把正文存成 `books\<书名>\novel.txt`（UTF-8）。

然后打开 `books\<书名>\book.json`，把 `bookName` 改成**番茄后台里一模一样的书名**。

### 4. 检查和发布

```
双击 9-检查小说格式.bat     看格式报告，把 [FAIL] 的都改掉
双击 8-发布前自检.bat       体检环境/登录态，它会预告"现在点一下会发几章"
双击 4-一键发布.bat         发
```

第一次用建议先双击 **`3-试运行(不发布).bat`** —— 它只填不提交，让你在浏览器里肉眼核对一遍填充是否正确。

## 日常使用

仓库根目录那堆编号 `.bat` 就是全部入口（文件名用中文方便双击，内容保证纯 ASCII 以免 cmd 乱码）：

| 双击这个 | 作用 |
|---|---|
| **`4-一键发布.bat`** | ★ 平时只用这一个 |
| **`12-打开管理面板.bat`** | ★ 图形化面板（见下节） |
| `11-切换当前小说.bat` | 换一本发 / 新建一本 |
| `5-查看进度.bat` | 哪些发了、哪些没发（含今日额度） |
| `10-查看今日额度.bat` | 只看"今天还能发多少字" |
| `9-检查小说格式.bat` | 换/改完小说后跑一次 |
| `8-发布前自检.bat` | 体检（会预告"点一下会发几章"） |
| `3-试运行(不发布).bat` | 演练，只填不提交 |
| `2-拆分章节.bat` | 只想单独看拆分结果 |
| `6/7-设置·取消定时发布.bat` | Windows 任务计划 |
| `1-首次登录.bat` | 登录态过期时重新登 |
| `0-安装依赖.bat` | 装依赖 |

命令行也都能用：

```bash
node src\cli.js check                   # 发布前自检（预告"点一下会发几章"）
node src\cli.js lint                    # 只校验小说格式
node src\cli.js status                  # 看进度
node src\cli.js daily                   # 看今日额度
node src\cli.js books                   # 列出账号里的作品（多书账号用这个确认书名）
node src\cli.js switch                  # 列出本地小说 / 切换当前发哪一本
node src\cli.js publish --dry           # 试运行：只填 1 章不提交
node src\cli.js publish --chapter 5     # 只发第 5 章
node src\cli.js reset --chapter 5       # 清掉某章的发布记录（重发用）
```

## 可视化面板

双击 **`12-打开管理面板.bat`**，浏览器会打开 `http://127.0.0.1:8787`。

- **四张指标卡**：已发布 / 待发 / 今日字数额度 / **点一次发布会发几章**
- **章节表**：章节号 · 标题 · 字数 · 分卷 · 状态，可按「全部 / 待发 / 已发」筛
- **实时日志**：命令行的输出通过 SSE 实时推到这里
- **按钮**：开始发布 / 停止 / 试运行 / 格式校验 / 重新拆分 / 发布前自检

几点说明：

- 面板和 `.bat` 是**同一套逻辑** —— 按钮背后跑的是同一个 CLI 子进程，不存在"两边算出两种答案"。
- **只监听 `127.0.0.1`**。这个面板真能把章节发出去，不能摆在局域网上。
- 一次只跑一个任务，重复触发会被拒（防重复发布）。
- 端口被占用会自动 +1（8787 → 8788 → …）。

## 小说文件的格式

一句话：**章节标题单独占一行，正文跟在标题下面。**

```
第一卷：云隐谷

第17章 星海归途

正文内容……

第18章 没人懂的校准滑块

正文内容……
```

- 标题必须写成「第N章 xxx」形式（中文数字也行：「第十七章 xxx」）
- 想分卷就单独占一行写 `第二卷：某处`（这一行之后的章节都归该卷；**卷名要和后台对得上**）
- 番茄要求**正文 ≥1000 字**才能直接发布，标题 ≤30 字
- 文件存成 **UTF-8**

完整规范（能认 / 不能认的写法对照表、Word 导出姿势、常见错误示例）见 **[`小说文件规范.md`](小说文件规范.md)**。

想让 AI 帮你写？把 **[`给AI的写作格式要求.md`](给AI的写作格式要求.md)** 整段复制发给 AI
（里面是自包含的提示词，不引用任何本机工具，AI 拿到就能产出符合规范的文本）。
也可以直接抄 [`novel-模板.txt`](novel-模板.txt) 的结构。

## 配置

**三个文件都是"你自己"的，仓库里不会带**（`.gitignore` 已排除），样板在 [`templates/`](templates/)。

| 真实文件 | 模板 | 不建会怎样 |
|---|---|---|
| `config.json` | `templates/config.example.json` | 用内置默认值，能跑 |
| `credentials.json` | `templates/credentials.example.json` | 不自动登录，需手动登一次 |
| `books\<书名>\book.json` | `templates/book.example.json` | 新建小说时自动生成 |

最常改的几项：

| 配置项 | 默认 | 作用 |
|---|---|---|
| `publish.mode` | `publish` | `publish` 直接发布 / `draft` 只存草稿 |
| `publish.dailyCharLimit` | `10000` | **每天能发多少字**（`0` = 关闭限制） |
| `publish.maxPerRun` | `0` | 每次最多几章（`0` = 不限，交给日额度卡） |
| `publish.contentCheck` | `basic` | 内容检测方式（`basic` 不限次 / `full` 每天 2 次） |
| `publish.aiGenerated` | `yes` | ★ **「是否使用AI」声明，这是你对平台的声明，请按实际情况自己选** |
| `publish.intervalSeconds` | `15` | 章与章的间隔（还有 `jitterSeconds` 随机浮动） |
| `browser.channel` | `auto` | 用哪个浏览器，`auto` = 自己挑（推荐） |
| `browser.executablePath` | 空 | 手填浏览器 exe 路径（给 360/QQ 这类没有官方通道的用） |
| `safety.minCharsForPublish` | `1000` | 低于这个字数不发布 |

> ★ **`publish.aiGenerated` 请务必自己确认**。这是提交时「发布设置」弹窗里的必填项，
> 是使用者对平台作出的声明。样板文件里的值只是占位，别照抄。

## 它是怎么做的（工程笔记）

这部分是给想看代码的人准备的 —— 也是这个项目里最花时间的部分。

**① 提交必须"多步推进 + 显式处理弹窗"，而且顺序不能反**

现代组件库（Arco / Ant Design）的按钮事件绑在 React 合成事件或外层容器上，
`el.click()` 这种原生点击**不触发** —— 必须用 Playwright 的真实点击。

每轮推进的顺序是 **先填必填项 → 再点选项 → 最后点确认**，并且**在处理完弹窗之后**才判断成功。
反过来会把"弹窗还开着"当成"操作完成"。

**② 弹窗里的选项不能交给"通用找按钮"逻辑**

番茄的内容检测弹窗里，两个选项外面套了一层容器 `div`，容器的 `innerText` 是两个选项文字拼起来的
（`仅基础检测\n全面检测`），而且面积更大 —— 通用逻辑按面积排序就会点中容器，**看起来点了其实没点**。
解法是专门的 `findDialogOption`：限定在弹窗内、优先真 `<button>`、放宽到 `div` 时要求文字**完全相等**。

**③ 必填项没填时，确认按钮是 `disabled` 的**

「是否使用AI」不选，「确认发布」就是灰的，点一万次也没反应，
而日志看起来一切正常（按钮存在、文字也对）。所以点之前必须先查 `disabled`。

**④ 成功判定分三层，页面文案只是最弱的一层**

| 层 | 做法 |
|---|---|
| 成功词表 | **按模式区分**。发布模式只认强信号（发布成功/提交审核成功），不认「已保存」—— 编辑器顶栏常驻「已保存到云端」，会误判 |
| 弹窗处理 | 必须在判定之前完成 |
| **后台独立核对** | 重新读一次后台章节数，变了才算真的发出去。**这层是唯一能拦住"谎报成功"的** |

验证不到就如实返回 `verified: false`，并在记录里标注 —— 宁可让人去核对一眼，也不要让他以为发出去了。

**⑤ 去重 key 不能只用标题，索引要"派生"不要"另存"**

标题是最容易被改的东西（改个错别字就变了）。所以判定"发过没有"走**双通道**：
按标题查，查不到再从标题解析出序号、摊一张「序号 → 记录」的表再查。

而这张表**不持久化**，每次读的时候从主表现摊 —— 两张表存同一件事迟早对不上，
派生 = 单一数据源 + 零迁移，还顺手解决了"同一序号有两条记录"的优先级问题。

> 这条兜底通道有个**必须记住的副作用**：它按序号认，所以**两本书共用一份记录就会串号**
> —— 第二本的「第17章」会命中第一本已发的「第17章」，静默跳过且不报错。
> 这就是"一本一份 `progress.json`"是硬要求、而不是洁癖的原因。

**⑥ 面板/自检/真正执行，必须共用同一个函数**

本地面板曾自己拼参数算"这次会发几章"，把一个字段名记错（`used` vs `chars`），
结果剩余额度算成 `NaN`，「装不下」永远不成立 → 面板显示"会发 7 章"，**实际一章都发不了**。

算出来的是个"看起来完全合理"的数字，**语法检查和单测都发现不了**。
后来抽成 `planNextRun()`，自检和面板都调它。

**同一件事只要有两处实现，迟早会算出两个答案，而且错的那一处往往长得像对的。**

**⑦ 测试**

```bash
node tools\test-progress-index.js     # 37 项：发布记录双通道识别（纯离线）
node tools\test-books.js              # 66 项：多书支持（纯离线，临时目录里造数据）
node tools\test-browser-detect.js     # 72 项：浏览器探测（纯离线，不碰真实磁盘）
```

这三个**毫秒级跑完、零副作用**。另有几个需要真实浏览器/真实账号的联调脚本
（`test-resolve-book.js` / `test-browser-launch.js` / `test-apply-volume.js`），见 [`tools/README.md`](tools/README.md)。

## 常见问题

| 现象 | 处理 |
|---|---|
| 提示"**缺少依赖 playwright-core**" | 依赖还没装。双击 `0-安装依赖.bat`（或 `npm install`）。装之前 `lint` / `status` / `daily` 仍可用，其余命令要等装完 |
| 提示"未登录" | 登录态过期，双击 `1-首次登录.bat` |
| 提示"字数不足 1000，跳过" | 番茄硬规则，把该章补到 1000 字以上 |
| 提示"**后台核对未通过**" | 按钮点完了但后台章节数没变，八成没真发出去。去后台看一眼 |
| 日志说"**放不进今天剩下的 N 字额度里**" | 正常，这一章留到明天。想今天就发就调大 `dailyCharLimit` |
| 日志说"**没能按书名定位作品**" | `book.json` 里 `bookName` 和后台书名不一致。跑 `node src\cli.js books` 看准确书名 |
| 日志说"**后台没有 XX 这个卷**" | 去后台章节管理页点「编辑分卷」建好，或把小说里的卷名改成后台已有的 |
| 提示"**没找到任何可用的浏览器**" | 装个 Chrome/Edge；或 `npx playwright-core install chromium`；或在 `browser.executablePath` 填路径 |
| 提示"浏览器都启动不了" | 最常见的是那个浏览器**正开着**、占了登录态目录 → 先关掉再试 |
| 提示"找不到标题/正文/按钮" | 番茄改版了。按 `tools\README.md` dump 一份 `logs\structure-*.json` 就能定位 |
| 一天的额度感觉算少了 | 你是不是在后台手动发过？脚本统计不到，用 `node src\cli.js daily --set 实际字数` 补上 |

更全的排查表在 **[`使用说明.md`](使用说明.md)** 第八节。

## 环境限制（未实测的部分）

如实写在这里，免得有人以为哪些已经验证过了：

- **定时发布（`6-设置每日定时发布.bat`）的开发环境无法实测** ——
  我这边 `schtasks` 被安全策略拦截，代码按标准用法写好，但没跑通过。失败时按 `使用说明.md` 第六节手动配置。
- **「从面板点一次真实发布」没有测过** —— 点一次就真发出去了，不能拿真实账号试。
  面板的其余按钮（校验 / 自检 / 试运行）都端到端测过。
- **`.bat` 只做了静态校验**（纯 ASCII + CRLF），开发环境拦 `cmd.exe`，没法实际双击验证。
- **只在 Windows + Chromium 系浏览器上验证过**。Firefox 有个"尽力而为"的通道，未实测。
- **浏览器探测**测了 13 种常见安装路径，但只在装有 Chrome 的机器上验证过端到端启动。
