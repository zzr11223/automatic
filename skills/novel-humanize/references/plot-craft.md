# 情节阅读与修订专项

> 规则综合自 zenstory-ai/oh-story-claudecode（plot-core-methods / story-review / structure 知识库，MIT）与 QIUZHIYI1352/webnovel-writer，已按"读已有小说、改已有小说"的场景改写。
> 用途：当用户要的不只是改字句，而是"帮我看看情节 / 结构 / 为什么不好看 / 节奏对不对"时，用本文件。它管**情节层**；`fiction-craft.md` 管叙事一致性（设定/伏笔/视角），`ai-flavor-checklist.md` 管字句层。三层可以分开交付，也可以串起来。

## 一、怎么"读情节"——情节阅读五步法

读小说不能只读句子。按下面五步把一本小说读成骨架，产出**情节地图**（这是情节层诊断的交付物，先有地图再下结论）：

**第 1 步：列章表**
用 `python scripts/split_chapters.py <小说.txt> --list` 拿到章节清单与字数；逐章补一列"这一章发生了什么"（一句话）和"这一章的功能"（推进主线 / 铺垫 / 爽点兑现 / 关系变化 / 信息揭示 / 过渡）。

**第 2 步：抽主线**
问三个问题：这本书的"**一件事**"是什么（主线 ≠ 升级，主线是可完成的一件事）？主角的目标是什么？主要的阻碍是谁/什么？
若主线答不出来，或写成"变强、崛起"这类元素——先记一笔：主线模糊（S1/S2 级问题）。

**第 3 步：标五要素（逐章或逐场景）**
对关键章节标注：**目标 → 阻碍 → 行动 → 反馈（收益 or 代价）→ 新期待**。
- 缺"阻碍"→ 情节没有张力；缺"反馈"→ 读者觉得白看；缺"新期待"→ 断档。
- 反馈栏只标两类：**收益**（拿到东西、变强、关系推进）与**代价**（损失、暴露、结仇、新麻烦）。连续多章只有代价没有收益 = 高危。

**第 4 步：画两条线**
- **情绪曲线**：每章标一个主情绪（爽 / 燃 / 压抑 / 悬疑 / 温情 / 平），看是否有高低交替——一直高压读者会麻木，一直低压读者会走。
- **期待线**：短期期待（下一章看什么）、中期期待（这一段怎么收）、长期期待（全书目标）是否同时在位。

**第 5 步：建线索台账**
- **hot / warm / cold 表**：谁是当前核心冲突（hot）、谁近期活跃（warm）、谁超期没露面（cold）。
- 回顾阈值参考：核心角色 **3-5 章**得有有效触碰，主要支线 **4-6 章**；闲置超期 = 读者会问"那个谁去哪了"。
- **伏笔台账**：埋在哪章 / 计划哪章回收 / 状态；正文伏笔和"谜语人"要分开——**信息延迟超过 3 章且中间毫无推进 = 谜语人**（要么删，要么提前给一点料），自然融入剧情的才是伏笔。

## 二、情节诊断清单（读完地图，逐项过）

### A. 主线与结构
- [ ] 主线能一句话说清，且是"一件事"；主线完成前不换锚点
- [ ] 三层目标同时运行：大目标（全书）→ 中目标（本卷/本阶段）→ 小目标（当前单元）
- [ ] 单元之间**嵌套**：下一个故事的期待线，在上一段高潮**前**就露出（不是完结后才现找）
- [ ] 过渡章没有空转：过渡必须维持至少一条活跃期待

### B. 冲突与代价
- [ ] 同一时期有 2-3 条矛盾线在跑，且互有关联（因果 / 利益 / 信息差）；解决一条时激活或加深另一条
- [ ] 冲突有代价——没有代价的冲突，反转没有分量
- [ ] 主角的胜利不是白给的：要么付出代价，要么留下风险/下一任务（纯奖励章除外，但收益要足够明确）
- [ ] 反派/阻碍够强：弱反派 = 主角赢也没意义；对手要有主动性
- [ ] 巧合克制：关键节点靠巧合推动超过 2 次 = 高危（机械降神/降智）

### C. 节奏与情绪
- [ ] 情绪曲线高低交替；高密度（冲突/推进）与低密度（铺垫/日常）交替出现
- [ ] 冷却期规则：同类事件不连续超载——大冲突/打斗最多连 2 章；每 5 章至少有一次关系深化或世界观展开
- [ ] **水章排查**：每章用一句话概括"这段在讲什么"（信息团）——概括不出来，或信息团与主线无关且可删 = 水章
- [ ] 兑现节奏（网文硬指标）：前 3 章兑现 ≥1 次、前 10 章兑现 ≥2 次且收益 ≥3 次；连续"只有成本"≤2 章；兑现空档 ≤8 章（详见 `webnovel-craft.md`）
- [ ] 高潮有梯度：小高潮（单元）—中高潮（卷）—大高潮（书），不是平推

### D. 期待与钩子
- [ ] 三层期待同时在线；"两长一短"（1 个短期目标 + 1-2 条长期线）
- [ ] 章末有落点：悬念 / 决定 / 发现 / 余韵 / 阶段目标——至少占一样（低压章不强求硬悬念）
- [ ] 钩子款式轮换：同一款式连用 ≥5 章 = 问题（参考 `fiction-craft.md` F7）
- [ ] 高潮公式体检（重要场次）：**蓄能 → 假胜 → 崩解 → 交叉死磕 → 悬置收尾**——缺"假胜"时，有没有别的情绪落差或明确兑现替代？
- [ ] 升级流加查：升级有没有"三差异"——能力质变 / 待遇变化 / 人际圈层；升级前后没差别 = 没有升级感

### E. 自嗨与读者视角
- [ ] 三问全答得出：写给谁看？他们要什么？本书给了吗？——答不出 = 自嗨
- [ ] 主角行为读者能理解、共鸣、接受吗？（动机链完整，不为剧情降智）
- [ ] 读者已知信息与角色已知信息，是分开管理的吗？（信息差是爽感的来源，不能乱给）

## 三、情节修改——分级与红线

### 红线（情节层加倍执行）

1. **情节级修改，逐档确认**：默认只出方案不动手；动结构（P2 及以上）前，必须让用户明确知道"这一改会改变什么"。
2. **不动三样**（除非用户点名）：主线的"一件事"与走向、结局、主角核心设定。这三样要动，单独列出来让用户拍板。
3. **改完必对账**：动过情节，就同步更新伏笔台账、时间线、人物状态卡、修改日志——情节比字句更容易改出矛盾。

### P1 轻调（不动事件，只改组织与铺垫）

- 补铺垫：加伏笔、补动机、加压力镜头（让后面的转折成立）
- 删水：砍掉信息团为零的段落和场景；过渡场景没信息量就跳过
- 换钩子：章尾落点换款式（悬念/决定/发现/余韵轮换）
- 加/减代价感：给白给的胜利补一个后果；给拖沓的段落减压
- 场景内信息微调：同一场景里谁先说、谁后说、什么时候亮牌

### P2 中调（动事件的组织，不动结果走向）

- 场景重排：同章内或相邻章的顺序调整（先给冲突后给解释）
- 合并 / 拆分章节：调节奏；给重要章加长、给水章合并
- **加一个小事件**：小冲突、小代价、小收益——不改主线，只加密度和代价感
- 回扣冷线索：给超期没露面的角色/支线一次"有效触碰"（推进、施压、改变关系，纯提名字不算）
- 拉 / 收期待：提前把下一段的目标露出来；或把过早揭晓的悬念重新压住
- 高潮补件：缺"假胜"→ 加一个先给希望再击碎的段落；缺"崩解"→ 让伏笔在绝境中集中引爆

### P3 深调（动结构，逐项确认）

- 增删支线、重构卷结构、重排高潮次序
- 重写单元故事链（前置铺垫 → 高潮设计 → 收束与新期待）
- 适用手法：设门槛（资源/成就/多条件/动态/收集）、AB 交替（压情绪→抬情绪）、大剧情拉期待（先定大爽点，分阶段抵达）、矛盾网（2-3 条线关联运转）
- 注意：P3 不是默认服务，必须用户明确要求 + 每一步确认；改完必须重算所有台账

## 四、情节阅读报告模板

```
# 《书名》情节诊断报告（第 X-Y 章 / 全书）

## 1. 情节地图
| 章 | 事件（一句话） | 功能 | 情绪 | 收益/代价 | 新期待 |
（长表可截断为关键章）

## 2. 主线与结构
- 主线（一件事）：……
- 层级目标：大 / 中 / 小 = …… / …… / ……

## 3. 两条线
- 情绪曲线：文字版走势描述（哪几章高压、哪几章失速）
- 期待在位情况：短 / 中 / 长 分别是什么

## 4. 问题条目（S1-S4）
| # | 位置 | 问题 | 证据 | 严重度 | 修改方向（P1/P2/P3） |

## 5. 修改方案
- P1 必做：……
- P2 建议：……（说明每一改会改变什么）
- P3 备选（需逐项确认）：……

## 6. 连续性与伏笔核对
- hot/warm/cold 异常项：……
- 伏笔状态：……
```

严重度口径：S1 破坏主线/人设/读者信任；S2 影响留存与节奏；S3 局部问题；S4 提示项。

## 五、与字句层流程的衔接

- **顺序**：情节诊断在前（先读骨架），字句修改在后（再改血肉）；两项可以独立交付——用户只要"读情节"就交情节报告，只要"去 AI 味"就交字句层报告。
- **互相节制**：情节层方案落地时，字句改写仍然遵守删除比例上限与"删除前九问"；反过来，字句层发现的情节疑点（如时间线矛盾），移交情节层出方案，不在润色里顺手改剧情。
- **交付建议**：情节级改动按 P1→P2→P3 分批交付，每批附"改动影响说明"（哪些伏笔/因果受影响、什么被同步更新）。
