# 小说去 AI 味 · 情感增强

把"AI 写的"改到"像人写的"：诊断 AI 味 → 出修改建议与方案 → 示范改写 → 全篇人味化 + 情感增强。

能力分三层：**字句层**（AI 腔、句式、节奏 → `ai-flavor-checklist.md`）→ **叙事层**（设定、伏笔、视角一致性 → `fiction-craft.md`）→ **情节层**（主线、冲突、期待、收益节奏 → `plot-craft.md`）。三层可独立交付，也可串行——用户要"读情节"就先读骨架。

## 五条红线（任何时候不违背）

1. **先诊断，后动手**：默认先给诊断与方案，等用户确认再改写。用户明确说"直接改"才跳过等待。
2. **保真**：不加事实、不丢信息、不改变确定程度（"可能"不能改成"确定"，"相关"不能改成"因果"）；删改必须有理由——空泛、重复、歧义、不合文体。**虚构豁免**：小说细节可以编（那是创作），但设定、人物逻辑、情节不能漂移。**情节层修改走"情节模式"**：只动用户指定层级，主线、结局、主角核心设定要动必须单独确认（见 `references/plot-craft.md`）。
3. **保留作者指纹**：先做声音校准——从人写样本里提取五项：句长习惯、用词偏好、标点习惯、句子开头方式、过渡方式。**样本的优先级高于本 skill 的一切规则**；没有样本时按文体推断。宁可少改，不可改成另一副腔调。
4. **克制**：没问题的句子不动。"模式清单是检查线索，不是词语黑名单"——拟人在小说里是笔法（"风推开了门"），不是缺陷；引文、专有名词、"讨论某个词"而非"使用某个词"的地方，一律不动。
5. **改最少，效果最大**：能改一个词就不改一句，能删一句就不重写一段；人名、地名、数字、章节名、专有名词优先保留。**删除比例上限**（按诊断档位）：轻度 ≤15% / 中度 ≤25% / 重度 ≤35%——不得整段删除正文；疑似 AI 味但拿不准的，标 `[需复核]` 保留，交给作者，而不是替他做决定。

## 信号强度（下判断的尺度）

- **强信号**：谨慎的写作者几乎不会这么写，出现一次即可列入修改（"五味杂陈""这一刻他终于明白""空气中弥漫着"）。
- **弱信号**：必须靠密度和共现判断（"轻轻""仿佛""其实"），孤立一处不要动。
- **共现原则**：同一段出现多个痕迹才下重手——这就是安全线。

## 第一步：判断走哪种模式

| 输入 | 用户意图 | 模式 |
| --- | --- | --- |
| 片段（≤800 字，粘贴） | "帮我改一下" | **轻量模式**：速诊表（3-5 行）+ 改写稿 + 改法说明，一次交付 |
| 章节 / 多章（文件） | "给建议 / 改稿" | **标准流程**：诊断报告 → 方案 → 示范 → 确认后批量改写 |
| 任意范围 + "看情节 / 结构 / 节奏 / 为什么不好看" | 只读故事层 | **情节模式**：情节阅读五步法 → 情节地图 → 诊断报告（S1-S4）→ 情节级方案（P1/P2/P3）；详见 `references/plot-craft.md` |
| 整本 / 长期连载项目 | "长期合作改稿" | **工程化流程**：全书体检 → 建档 → 分批改写 → 整本终检（见下方"整本 / 多章批量流程"） |

## 标准流程

**Step 0 建档**：确认文本来源（粘贴 / 文件路径）、题材、人称、目标读者、发布平台、大概字数；若稿子是"AI 初稿 + 人工修改"的混合体，问清哪部分像 AI、哪部分是人写的（人写部分就是声音样本，至少 2-3 段、合计 300 字以上）。

**Step 1 通读 + 定标**：全文通读（长文先抽读头 / 中 / 尾各一章）。同时完成两件事：标出"AI 重灾区"，摘出"声音样本"。

**Step 2 逐维诊断**：加载 `references/ai-flavor-checklist.md`（16 维 + 信号强度 + 量化阈值），长文先跑 `scripts/scan_ai_flavor.py` 拿词表、结构模式与量化指标线索。每条结论必须附原文证据（位置 + 引用）。**叙述类问题（设定漂移 / 伏笔 / 节拍 / 视角）另按 `references/fiction-craft.md` 检查。情节类问题（主线 / 冲突 / 情绪曲线 / 期待与伏笔管理 / 收益节奏）先按 `references/plot-craft.md` 的"情节阅读五步法"读成骨架再下结论——用户要"读情节"时，情节地图就是主交付物。**

**Step 3 出报告与方案**：按 `references/revision-report.md` 模板产出：评分表 + 问题条目表 + 三档方案（A 轻润 / B 中改 / C 深改）。然后问用户选哪一档。

**Step 4 示范改写**：先只改 1-3 段有代表性的段落，给出"原文 / 改后 / 改法说明"对照。用户认可风格后再进入全篇。**不要跳过示范直接交全稿**——返工成本极高。

**Step 5 批量改写**：加载 `references/humanize-techniques.md`（手法库 + 保真原则）与 `references/emotion-enhance.md`（情感增强），改网文时另加载 `references/webnovel-craft.md`（修订守则 / 收益节奏 / 句长基准）。按章 / 按批处理（每批 2000-4000 字），每批附"本批修改点摘要"。长篇同步维护：人物声音卡、设定卡、伏笔台账（`fiction-craft.md` 第五节）。

**Step 6 终检（五件套）**：① **重跑扫描脚本**——模型自己看不见自己的统计习惯，改完常见破折号超标（真实教训：某次改写清掉了拟人化，却引入了 6 倍超标的破折号）；扫含章末摘要的改稿时，先剥离摘要区（`---` 之后）只扫正文，避免元信息污染指标；② 保真核对（数字 / 时间线 / 称谓 / 因果 / 限定语 / 否定是否漂移）；③ 反向复扫清单 + 一致性检查；④ 朗读一章找磕绊；⑤ **字数与节奏核对**——删除比例未超档（轻/中/重 ≤15/25/35%）；反向检查"过度压缩"：句均 <15 字、短句成片即电报体，需合并回校；工程词（细纲/情节点/大纲）不得出现在正文。

## 整本 / 多章批量流程（工程化模式）

适用于多章或整本（几万字到上百万字）。思路：**先体检、分批改、用文件当记忆**——不追求一次吞下整本。

0. **准备：单文件先拆章（若需要）**
   `python scripts/split_chapters.py <小说.txt> --out <章节目录> [--from N --to M]`
   自动识别编码（UTF-8 / GBK）与"第X章 / 第X回"标题；不修改原文件。只做部分章节时用 `--from / --to`；`--list` 可先看章节结构。
1. **全书体检（不改稿）**
   `python scripts/scan_ai_flavor.py <章节目录> --csv report.csv`
   拿到逐章指标表 → 分级：重灾章 / 中等章 / 干净章。**不平均用力**：优先改前 3 章（读者留存关键）、高潮章、重灾章；干净章只轻润或不动。CSV 表同时当进度台账用。
2. **建档（一次性）**
   在 `outputs/` 下建工作文件：`00-设定卡.md`、`00-伏笔台账.md`、`00-人物声音卡.md`、`00-修改日志.md`（模板见 `fiction-craft.md` 第五节）；从"干净章"抽 2-3 段当声音样本。
3. **试改锁定风格（1 章）**
   完整改 1 章给用户确认 → 锁定修改幅度档（A/B/C）与口语度。之后各批按同一标准执行。
4. **分批改写（每批 2000-4000 字，按章切批）**
   每批交付 = 净稿 + 修改点摘要（3-5 行）+ **连续性交接条**（本批人物状态变化 / 伏笔增删 / 下批注意的语气与设定）。每批对照设定卡与声音卡复查，更新修改日志。用户要分批交付就改一批交一批；要一次交全本，就按批跑完整合。
5. **整本终检（一次性）**
   重跑体检对比改动前后；全局核对：首尾对齐、承诺对账、伏笔台账逐条、数字表交叉、钩子款式分布；抽 3 章朗读。

规模参考：几万字（短篇集 / 中篇）→ 分 2-3 批一次通改；十几万字（一本书）→ 逐章批处理；百万字（连载）→ 严格工程化，只改关键章，其余滚动批处理。

## 核心手法速查（细节见 references）

- **减法优先**：删升华句、删解释句、删过渡句、删万能副词（不禁/缓缓/轻轻地……），删完再回填 <5%
- **情绪外化**：不写"他很难过"，写他做了什么小事
- **抽象沉降**：抽象词 → 具体物证 + 动作 + 数字（"很拮据"→ 发霉的烟头堆）
- **节奏手术**：叙述以逗号长句为默认（逗号之间 8-12 字、整句 20-30 字），连续 3 句超 35 字必拆，重击处单句成段；**反向也要防**——全篇碎句 = 电报体，与 AI 腔同级的问题（网文基准见 `references/webnovel-craft.md`）
- **对话活化**：打断、沉默、答非所问、动作插入、每个角色一个口头禅（遮住人名能认出人）
- **比喻重建**：从人物身份 / 经历里长出来，宁可粗糙不要通用；单场景意象域统一
- **不完美注入**：冗余动作、小失误、无用的细节——这是人味的主要来源
- **欧化修复**："的"字链拆句、被字句改主动、形式动词还原、"通过……使……"删框架、省略代词（见手法库第十一节）
- **情感三要素**：代价 + 选择 + 延迟反应（见 `references/emotion-enhance.md`）

## 长篇一致性（整本 / 连载必做）

按 `references/fiction-craft.md` 执行：设定卡（防人物/世界漂移）、伏笔台账（防挖坑不填）、数据时间线表、人物声音卡（防对话同质化）、修改日志；另查节拍平均、OOC、视角泄漏。网文格外注意：**改稿不得拖慢爽点节奏，钩子款式要轮换**。

## 输出与交付规范

- **粘贴短文本**（默认）：最终改写稿 + 简短说明；不要附冗长的"改写仪式"（自评分、完整命中清单）——用户要诊断时才给报告。
- **诊断报告**：markdown（评分表 + 问题条目表 + 方案），可直接给用户看；报告要克制，没问题的段落明说"可以不动"。
- **文件模式**：改写稿一律**另存新文件**，不覆盖原稿；仅改正文，代码块、URL、元数据、表格结构保持原样。
- 文件组织：产物放 `outputs/` 下，如 `01-诊断报告.md`、`02-第01章-改后.md`；长篇净稿 + 章末修改摘要。
- 若用户后续要接自动发布流程，分章 txt 的标题行格式与 `cn-web-auto-publish` skill 的源文件约定对齐即可。

## 常见坑（避免帮倒忙）

- **改过头**：把作者刻意的口头禅、重复修辞、个人风格当 AI 味删掉；把小说的拟人笔法当缺陷
- **情感加过量**：煽情本身是另一种 AI 味；情感要克制、要有代价
- **只加不删**：字数膨胀，节奏变拖
- **过度压缩**：把所有句子都拆成短句 = 电报体，AI 腔的同级问题；拆句目标是"逗号间 8-12 字、整句 20-30 字"，不是越短越好
- **整段删除 / 删除超档**：删除比例超出档位上限，或删掉了伏笔、钩子、爽点铺垫——这是事故；拿不准的标 `[需复核]` 而不是动手删
- **全篇文艺腔**：正确目标是"像一个具体的人写的"，不是"像文学杂志写的"
- **忽略题材**：古风不能出现现代词，都市别掉书袋，网文的爽点节奏不能改慢
- **改完不复查统计习惯**：人（和模型）改稿时容易引入新的重复模式，必须重跑扫描
- **平台口味**：不同平台读者偏好不同（番茄偏快、起点偏设定、晋江偏情绪细），改稿前先问目标平台
